# C-15 / EJ-8 — Número fijo de consultas en el detalle de una orden (RT-TX-06)
# ============================================================================
# Qué demuestra: el detalle de una orden usa el MISMO número de consultas
# independientemente de cuántos ítems tenga. La orden 1 del seed tiene 2 ítems
# y la orden creada por el bloque C-15 de test/ordenes.http tiene 4 ítems:
# los dos GET /ordenes/{id} ejecutan exactamente 5 consultas cada uno
# (usuario, asignacion_rol, orden con vehiculo y cliente, items con repuestos,
# historial de estados) — la carga anticipada evita una consulta por ítem.
#
# CÓMO PRODUCIR ESTA EVIDENCIA:
#   1. Migrar y sembrar:  alembic upgrade head && python seed.py
#   2. Arrancar la API con las consultas visibles en la consola:
#        set SQL_ECHO=true   (o SQL_ECHO=true uvicorn main:app --port 8000)
#   3. Con la extensión REST Client sobre test/ordenes.http: correr primero el
#      bloque de login de recepción (o C-10) y después el bloque C-15, que crea
#      la orden de 4 ítems y pide ambas. Guardar el fragmento de consola.
#   4. Verificar: entre el BEGIN y el COMMIT de cada GET aparecen 5 SELECT,
#      los mismos en la orden de 2 ítems que en la de 4.
#
# La misma aserción, en automático, la hace
# test/pytest/asincronia/test_consultas_fijas.py (conteo exacto por sesión propia).
#
# Nota sobre el id: el de la orden de 4 ítems depende del estado del seed
# (en una base recién sembrada es la 3; en el recorrido completo de
